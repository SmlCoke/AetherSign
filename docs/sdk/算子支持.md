# A1-AI-Tool ONNX 算子支持说明

在使用 A1-AI-Tool 工具链进行 ONNX 模型编译时，模型中的算子需要满足工具链的支持范围和参数限制。  
如果模型包含不支持的算子或超出限制的参数组合，可能会导致 编译失败或性能下降。

本文整理了当前工具链 支持的 ONNX 算子列表、限制条件以及模型设计建议，供模型开发与部署时参考。

## 一、当前支持的 ONNX 算子

目前 A1-AI-Tool 工具链支持的主要算子如下：

| ONNX算子 | 限制说明 |
| --- | --- |
| Conv | Kw,Kh,Sw,Sh,Pw,Ph 均不能超过 16；单个卷积核（Kw × Kh × Cin）不能超过 2048 |
| AveragePool | 无特殊限制 |
| GlobalAveragePool | 无特殊限制 |
| MaxPool | 最大支持 8×8 |
| BatchNormalization | 无特殊限制 |
| Add | 无特殊限制 |
| Mul | 无特殊限制 |
| Concat | 支持 C通道拼接 |
| Split | 支持 C通道拆分 |
| Relu | 无特殊限制 |
| LeakyRelu | 仅支持 alpha = 0.1 或 0.01 |
| Transpose | 支持4维tensor维度重排， perm = [0,2,3,1] |

缩写说明：K=卷积核(Kernel)、S=步长(Stride)、P=补边(Pad)、C=通道(Channel)、w/h=宽/高(Width/Height)

## 二、常见不支持的算子

在实际模型中，一些算子虽然在 ONNX 中常见，但当前工具链不支持或者效率较低，例如:

- Sub
- Div
- Transpose
- **Softmax（利用率较低）**

这些算子通常**不是主干网络的一部分**，而是出现在：

- 检测模型后处理
- 分类概率计算
- 特征格式变换
- anchor / box decode
- normalization

例如典型后处理：

```text
box = (pred - mean) / std
score = softmax(logits)
```

这些操作一般会包含：

- Sub
- Div
- Softmax
- Transpose

因此很容易导致 编译失败。

部分算子虽然可能被支持，但 计算效率较低，例如：Softmax，即使能够编译，也可能 拖慢整体性能。

## 三、推荐的模型结构设计

为了提高模型在 NPU 上的 可编译性与性能，建议建议将后处理部分从 ONNX 网络中移除，改为 CPU 实现。

例如：

原始模型：

```text
Backbone -> Head -> Transpose -> Softmax -> Sub -> Div -> Output
```


推荐改为：

```text
Backbone -> Head -> Output (raw tensor)
```

然后在 CPU端进行后处理：

```text
CPU:
transpose
softmax
bbox decode
nms
```

优点：

- 避免 unsupported op
- **NPU 专注高计算密度部分**
